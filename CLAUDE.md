# CDE-Map: notes for Claude

An unofficial, phone-friendly viewer for the draft ACR-RSNA next-gen CDE ontology, hosted on GitHub Pages at https://towbinaj.github.io/CDE-Map/ and used as an iPhone home-screen app. The owner is Alex (towbinaj). The map is draft committee work, so the app is always labelled "unofficial viewer".

## Data sources (all public, read live from GitHub; nothing is copied into this repo)

Branch `next-gen-2026` of RSNA/ACR-RSNA-CDEs, under `docs/next-gen-schema/`:

- `alpha/visualizations/ontology_map.html`: PyVis page generated by RSNA's `ontology_visualizer.py`. The 3D map reads only the two inline JSON lists (`nodes = new vis.DataSet([...])`, `edges = ...`). No RSNA code runs. It has about 738 nodes, including RadLex anatomy ancestry added for display. Each node's `title` holds a "Definition:" line.
- `graph/relationships.jsonl`: definitions of the relationship terms (HAS_VALUE, SCOPED_TO…). "has category" comes from `alpha/radcde-alpha.ttl` instead (hard-coded in `index.html`). RadLex anatomy terms (part of, branch of…) have no definitions anywhere, in either RSNA's repo or RSNA/RadLex.
- The canonical graph used by Card, Tree and List: `alpha/graph/definition-graph.json` (the reviewer's base) plus `graph/*.jsonl` (additions, listed through the GitHub contents API with a fallback list). It is merged by the rules of RSNA's `tools/foundation.py`: additions never replace base items, and `"overlay": true` lines only add props to a matching base edge.
- Commit date for the status line: `api.github.com/repos/RSNA/ACR-RSNA-CDEs/commits?sha=next-gen-2026&path=...`.

## Files

- `index.html`: the 3D app (3d-force-graph, orbit controls, starfield, label overlay canvas), the details panel, Trace, Focus view, Definitions, the view switch and data loading.
- `map-data.js`: reads `ontology_map.html` (nodes, edges, definitions), parses `relationships.jsonl`, and extracts RSNA's focus-rules script. Shared with the daily check.
- `canonical.js`: merges the canonical graph and computes inherited ("effective") definitions over SUBTYPE_OF, like `foundation.py`. Shared with the daily check.
- `browse.js`: the Card (RSNA's "mat" layout from `tools/render_cards.py`), Tree and List views. The Tree has four sections, each built from one kind of link: "Where it is" (scope, then RadLex location links such as Part_Of and Contained_In from the 3D map's data, one chain per place with other parents noted on the row; no subClassOf), "What it is a kind of" (SUBTYPE_OF outline), "What you record about it" (elements and measurements) and "What can cause it" (incoming MAY_MANIFEST_AS / MAY_CAUSE; outgoing ones for diagnoses).
- `sw.js`: service worker (`cde-shell-vN`). It serves the app network-first and the versioned engine cache-first. **Bump `SHELL` when the list of app files changes.**
- `lib/3d-force-graph-1.80.1.min.js`: self-hosted engine (MIT, from the npm tarball, integrity checked).
- `.github/workflows/check-rsna-map.yml` + `.github/scripts/check-rsna-map.js`: daily check at about 6 am Eastern, also run on pushes to `main` that touch the reading code. It opens an issue if the map, the terms list or the canonical graph can't be read, or if RSNA's focus-rules script changes (its hash is kept in `.github/rsna-rules.sha256`).

Saved on the device: Cache API `cde-map-v2` (`/last-good-map.json`, `/last-good-relationships.json`, `/last-good-canonical.json`) for offline use and as a fallback when GitHub data is broken. localStorage holds `cde-layout-<hash>` (settled 3D positions) and `cde-defs` (the Definitions toggle).

## How the app behaves (Alex's decisions)

- 3D globe view, chosen over flat 2D.
- **Tapping a concept opens Trace.** It follows the arrows both ways as far as they go: "Comes from" (amber) and "Goes to" (teal), grouped by steps away, with Steps 1/2/3/All. Anatomy twin links (part of / has part, and similar) are followed one way only, so chains don't loop.
- **Focus view** button: RSNA's "semantic neighborhood" rules, ported from their page as of 26 Oct 2026. They don't follow RSNA's changes automatically; the daily check flags changes.
- Concepts outside the focus stay visible in grey and can be tapped. A tap picks the nearest concept within about 30 px. Node dragging is off.
- **Definitions** toggle (remembered on the device): concept definitions under each concept, plus a "Terms used" glossary.
- **Map · Card · Tree · List** switch: the selected concept carries across views. Concepts that exist only in the canonical graph (groupings) show a note on the map.
- Find path was built and then removed (Trace replaced it).
- The Card, Tree and List use the 3D map's colour for each concept type, so a type looks the same everywhere. Every concept, element and measurement is a coloured-tab box.
- Wording in the app and README is neutral: it is a joint ACR-RSNA project used by anyone, so avoid "RSNA's …". Repository names and links stay as they are.

## Testing before publishing

There is no build step. Serve the folder (`python3 -m http.server`) and drive it with Playwright in headless Chromium at 390x800 (phone) and 1440x900 (desktop). Route `raw.githubusercontent.com` and `api.github.com` requests to local copies of RSNA's files. Check for page errors, and screenshot new UI to look at it. The check script runs locally as `node .github/scripts/check-rsna-map.js <ontology_map.html> [relationships.jsonl]`.
